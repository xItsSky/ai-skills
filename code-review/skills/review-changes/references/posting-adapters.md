# Posting Adapters

Post findings only when the target is a pull or merge request and the platform CLI is authenticated. Post as review comments. Never approve, merge, or send a request-changes event.

## GitHub

Summary comment on the review:

```bash
gh api --method POST /repos/{owner}/{repo}/pulls/<n>/reviews \
  -f body="First-pass review generated by Claude Code. Comments follow Conventional Comments. Blocking items should be resolved before merge." \
  -f event="COMMENT"
```

Inline comment on a changed line:

```bash
gh api --method POST /repos/{owner}/{repo}/pulls/<n>/comments \
  -f body="<conventional comment>" \
  -f commit_id="<head sha>" \
  -f path="<file>" \
  -F line=<line> \
  -f side="RIGHT"
```

Use `event="COMMENT"` only. Never `APPROVE` or `REQUEST_CHANGES`.

## GitLab

Note on the merge request:

```bash
glab mr note <n> -m "<summary>"
```

Inline discussion on a changed line, through the API:

```bash
glab api --method POST "projects/:id/merge_requests/<n>/discussions" \
  -f body="<conventional comment>" \
  -f "position[position_type]=text" \
  -f "position[new_path]=<file>" \
  -f "position[new_line]=<line>" \
  -f "position[base_sha]=<base sha>" \
  -f "position[head_sha]=<head sha>" \
  -f "position[start_sha]=<base sha>"
```

## Rules

- Comments only. No approve, no merge, no request-changes.
- Put each finding on its line where possible. Fall back to a file-level or summary comment when the line is not part of the diff.
- Keep the Conventional Comments format exactly.
